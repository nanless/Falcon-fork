## 前期复核中已确认的错误与边界

1. `AudioBlock` 四个尺度均执行各自的频率 LSTM、时间 LSTM、注意力；最深层在下行执行，较浅三层在上行执行。用随机 2 秒输入 hook 验证两遍各层形状分别为 251×129、126×65、63×33、32×17。
2. 默认 `VideoBlock` 把 `[B,T,C]` 送入 `batch_first=False` LSTM。官方 small 权重、随机输入隔离实验：保持批中第二条音视频不变，仅替换第一条视频，第二条波形 max 差 0.001682、RMS 差 0.0001508；改用 batch_first 后同一对照为 0。随机视觉特征实验不代表真实质量变化。
3. Space 一次接收完整录音，但内部以 2 秒窗、0.5 秒步长处理，默认最多 32 窗成批；Studio 单窗。真实 LRS2 tt 第 0 条、真实 FRCNN 与发布 small 权重的实验，batch 1 对 batch 4：输出差 RMS 0.00027224、峰值差 0.00436008；输出 RMS 0.0957676，目标 SI-SDR 分别 9.54826 / 9.55840 dB。单样本不可推广；与前一隔离实验结合判断批次耦合。
4. `paper_causal=True` 时 stride 2 卷积的输出裁剪过多，2 秒输入各级时间长度从 251→251→126→63→32 变为 251→251→124→60→28。该开关不只是改变 padding，历史关于其几何前视的结论需修正后重测。通用 ConvNormAct 的 causal kernel=1 还会发生 `:-0` 空切片；不是当前默认已检查路径的故障。
5. paper 训练池 40,000 条是 20,000 混合的双目标方向；有放回抽 10,000 条的期望覆盖约 22.12% 方向条目、39.35% 唯一混合。配置和多个文档将前者称唯一 mix，口径错误。
6. paper tr 等间距抽 40 条（含两个方向），`mix-target-near` RMS 为 1.448e-5 至 1.543e-5，拟合系数相对 1 的最大偏差 1.18e-5。旧文根据脚本未再次乘 g2 就断定 near 与混合分量不同，不成立；数据文件本身已含比例。
7. 直接对 NASS 损失和 query 梯度做对照：K=1 时 beta=0/1/100 均为 0.7343966961 且梯度相同；K=2 时 beta 改变损失与梯度。当前 paper 数据 K=1，退火不改变该损失。K=0 时正项仍存在，不能说整个 NASS inactive。
8. 复算四份 LRS2/RealSSA 核心 CSV：LRS2 两表 SI-SNRi/SDRi 各 3000 有效；RealSSA 两表 SI-SNRi 9169、SDRi/PESQ 9166；计算均值与 CSV avg 行一致。另检查十份相关 CSV，未发现 inf。汇总代码 `notna` 可能把未来的 inf 当有效，是潜在边界而非已证明历史结果受影响。
9. `audio_train.py` 实际硬编码 DataModule 和 NASSv2 类，配置 `data_name` / `training.system` 在现有入口不是动态分派。六份现有配置符合该实现，换字段不会切换类。
10. 数据转换脚本相同输出目录先生成 s1 再用 s2、默认不 overwrite，且 s2 mouth 已存在时，可能跳过已有 target 音频但重建 s2 mouth 索引；临时模拟复现状态 skipped_existing。现存数据是否受影响仍待验证。
11. `realssa_sim_tt_pipeline.sh` 名称中的 dry-run 并非无副作用：仍创建目录、追加日志和探测；固定目录的旧评测脚本可能覆盖证据。未运行上述脚本。
12. 掩码 ReLU 的相位限制作用于可学习的特征对；后面还有可学习解码到真实频谱，不能推出最终 STFT 相位范围。

## 后续复核发现（2026-11-10）

- 现存目标错配检查：旧版三个划分的 28,000 个 mouth ID 均对应 s1，等间距抽样 600 条旧 target 与源包 s1 的文件 SHA-256 一致；paper 56,000 条索引的目标、mouth 和 near 路径语义一致。旧版音频只是抽样；paper 是路径检查，并不证明所有波形或人脸身份均正确。
- `tools/repro/lrs2_2mix_to_falcon.py:447–454` 的 total_seconds 将样本数频数之和除采样率，未乘每种长度，已有旧版 `conversion_stats.json` 的 tr/cv/tt 因此分别约 1.2/0.3/0.2 秒；按 20000/5000/3000 条、每条 2 秒应为 40000/10000/6000 秒。该字段不改变音频或索引长度。
- 历史 `gap_analysis.py` 对不同 utterance 批量推理，P2A small-200 日志显示主要使用 batch 4。由已验证的批次耦合可知，P2A 部分消融结果可能混入前序样本的影响；历史原批次和整体影响尚未量化；后续当前样本已有定向对照，不能一概作废，也不能推广到其他脚本。
- `studio/infer_file.py:28–39` 将四字节 WAV 按 float 解释；临时 PCM32 整数 WAV 测得输入 [0,0.5,-0.5,约1,-1] 被读为 [0,2,-2,nan,-0]。不影响其正常 16-bit 路径；float 格式兼容边界当时待验证，后续已确认见下文。
- 对 117 个跟踪 Markdown 自动检查（剔除代码块及行内代码），240 个相对路径引用均在当前服务器文件系统存在；此项只检查路径存在，不检查 anchor、语义或目标内容真伪。
- 时频注意力构造 `[B*4,T,T]` 分数；按 60 秒约 7501 帧、float32 和 B=1 估算，单个最高尺度分数张量约 900 MB，不含其他张量。是计算估算而不是内存实测。
- 对转换验收的二次复核：临时构造 s1 音频配同混合的 s2 嘴部后，转换器 `validate_outputs` 仍报告 length/mouth/mix_sum/near 全部通过；因此校验通过不能单独证明目标嘴部与音频方向一致。另 `--limit` 只约束转换任务，索引重建会扫描已有输出；已有完整输出目录上不保证得到 N 条子集，此条目前是源码推断。
- 模型组独立复核训练数据论断：索引 K=1 不保证运行时 K=1，因为 near 若与 mix 路径相同、太短或读取异常会被跳过；正常文件读取成功时为 K=1。22.12%/39.35% 是独立均匀抽 10000 次的数学期望，不是实际覆盖率，真实 DDP 丢批和随机采样会改变结果。
- `audio_train.py` 的条件式 rank 分桶 `all_gather` 与训练结束无显式 rank-zero 写出保护已再次按源码核查；均为多卡风险推断，尚无真实 DDP 故障复现。
- 当前 Python 3.11 用 soundfile 生成 IEEE float32 WAV 后，`studio/infer_file.py::read_wav` 抛 `wave.Error: unknown format: 3`；其宣称的浮点 WAV 支持在该环境不可用。PCM32 整数又被静默解释为浮点，两种情况应分别处理。
- P2A 抽样规则 seed=0 的首批索引 7/15/23/43：真实前端及 small 权重整段推理，batch 4 相比单条，第 0 条 RMS 差约 1.54e-8，后三条分别 1.014e-4、7.369e-5、1.838e-4；SI-SDR 差约 +0.00068/−0.00228/−0.00514 dB。仅首批；脚本与 JSON 已保存在 `./`。
- 多卡近场 all_gather 与结束导出的风险仍未在真实 DDP 验证。Space 对同一真实样本 batch 1/4 的差异由两个方向独立复现。
- 操作脚本继续复核：`realssa_sim_tt_pipeline.sh` 无 `set -e`，执行阶段可能在子步骤失败后继续并最终退出 0；`run_p2d_train.sh` 与头注释不同，启动前截断日志；`resume_when_network_ok.sh` 注释的 1.0 MB/s 与代码 350000 B/s 不一致，触发的 stage=all 含 rsync 删除已迁移源文件。均为源码检查，未运行。
