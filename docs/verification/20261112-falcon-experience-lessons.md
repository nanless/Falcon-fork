## 一、先把用户要求写成可测条件

需求在讨论中逐步明确，早期和最终方案的时间语义不同。应记录每次决策的适用版本。

| 需求维度 | 最终约定 |
| --- | --- |
| 输出节奏 | 每次输出 120 ms 音频；16 kHz 下为 1920 个采样 |
| 可用未来 | 当前块结束后，音频与视频共允许 80 ms 前视；所有模块共享预算 |
| 可用历史 | 可以使用过去音视频特征及状态；递推状态按 120 ms 推进，边界重建频谱使用本块允许的前视 |
| FRCNN | 使用预训练视觉骨干并冻结；原 5 帧对称时间卷积需要后续 2 帧 |
| 音频模型 | 音频编码、融合及分离网络从零初始化；不加载旧分离器或教师 |
| 训练数据 | RealSSA-Sim 官方 tr/cv/tt；训练和验证用途与测试分开 |
| 批量与更新 | 双卡每卡 batch 1024，全局 2048；一个 batch 一次损失、一次反向、一次更新，不做梯度累积 |
| 学习率 | 目标 0.01，1000 次成功更新预热；验证调度和异常梯度门控可降低实际峰值 |
| CPU | 完整视觉与音频模型按 120 ms 输出块测量；目标为测量样本中的最大单块处理时间低于 60 ms |
| 实验位置 | 数据索引、运行日志、检查点、基准及评测结果位于服务器 /root/group-shared/voiceprint/experiments/ 的子目录 |

最初讨论过不看后续块的严格 chunk-wise causal；用户随后明确允许 80 ms 音视频前视。当前实现称为**有界前视的流式模型**：当前输出块可以依赖边界后 80 ms 的输入，块与块之间持续推进并保留历史。

### 流式时钟

25 fps 视频每 40 ms 一帧。当前三帧为 A、B、C，后续两帧 D、E 提供原 FRCNN 的右侧上下文：

    时间          0       40       80       120      160      200 ms
    视频          A        B        C         D        E
                  |------- 当前输出块 -------|--- 未来上下文 ---|
    音频          |--------- 1920 点 --------|--- 1280 点 ------|
    视觉计算      历史2帧 + A B C + D E → A B C 的视觉特征
    下一块                                     D E ...

视觉历史只保存当前块最后两帧；未来帧会在下一个块重新作为当前输入。若为 D、E 再计算完整对称 FRCNN 特征，就还需更晚的帧，原始视频前视会超过 80 ms；当前分离器只使用当前三帧的原样视觉特征，未来音频位置沿用末帧视觉条件。

音频尾部、时间卷积、LSTM、注意力及视觉递推历史仅推进当前块；重叠相加的边界频谱缓存的是本次预测的索引 15（从 0 开始）的频谱帧，即第 16 帧。该帧可使用当前块允许的 80 ms 前视，下一块重建时复用，以保持交叠部分一致。它与递推状态的提交含义不同。

首次输出等待 120 ms 当前输入和 80 ms 前视，再加模型计算。CPU 单块计算耗时和音视频采集等待属于不同数字，网络和浏览器耗时不计入本任务约定。

输入序号、形状或有限性检查未通过时当前 tick 不会被接受，修正后可重发同序号；会话处理器异常、输出非有限或长度不对时，已接受输入留在队列且旧状态不提交：`push()` 阶段用 `retry_ready()` 重试，`finish()` 阶段再次调用 `finish()`，尾块完成后一次返回。处理器应将传入状态视为只读；会话不能恢复外部处理器对状态的原地修改。

[在线检查点适配器](../../tools/streaming/paper_live_inference.py) 将模型与会话连接，逐次接收 40 ms 单声道音频及已归一化嘴帧，并在收齐五个 tick 后开始按三 tick 输出；采集、嘴部检测与裁剪、网络连接不属于该适配器；指定 `threads` 会改变当前 PyTorch 进程的线程设置。一次 SDR 烟测 checkpoint 的完整会话测试中，4 线程预热 100 块、记录 500 个产出块的输入转换、缓冲、前向和 CPU 输出，最大为 40.93 ms、无块达到 60 ms；不包含采集、检测、裁剪或网络，完整记录见 `/root/group-shared/voiceprint/experiments/falcon_paper_lookahead_20261112/online_session_sdr_b1024_cpu4_20261112.json`。 后续在训练并行运行时用固定重复随机输入实测 500 输出块，单次产出 push 最大 40.100 ms，逐块累计全部 push 的 CPU 处理耗时最大 40.229 ms；各 0 块达到 60 ms。测量范围不含采集等，源码、权重哈希及逐块数据见 `/root/group-shared/voiceprint/experiments/falcon_paper_lookahead_20261112/online_session_final_aggregate_cpu4_20261112.json`，复测入口为 [benchmark_paper_live.py](../../tools/streaming/benchmark_paper_live.py)。详见 [视觉编码器](../../look2hear/models/FalconLookaheadVisual.py)、[流式缓冲](../../tools/streaming/lookahead_session.py) 和 [时间与末尾测试](../../tools/repro/tests/test_falcon_lookahead_stream_e2e.py)。

## 三、围绕论文做变更，逐项说明差异

论文中的视觉预训练、时频分离、多尺度信息交互、复数掩码和近场说话人对比目标是互相关联的设计。早期自建流式方案一次替换了主要分离架构、输出方式、损失和数据划分，后来将其当作“只改流式”讨论，导致质量差距无法归因。随后恢复以论文结构为参照，当前模型仍是新写的流式近似，而非发布 Falcon 的逐层等价移植。

| 环节 | 论文或公开实现 | 当前流式实现 |
| --- | --- | --- |
| 视频 | FRCNN 对称 5 帧前端；论文报告整条视觉分支 120 ms 前视 | 额外提供两帧视频以原样计算当前三帧特征；全模型预算按块边界后 80 ms 约束 |
| 音频分析 | 256 点 Hann STFT、128 点 hop，实部、虚部和幅值输入 | 使用相同窗长、帧移与输入种类，分块携带状态 |
| 分离主体 | 多尺度时频编码与跨尺度交互，频率和时间建模 | 四级频率尺度、跨尺度融合、频率双向 LSTM、时间单向 LSTM、历史注意力与时间卷积 |
| 输出 | 复数掩码及学习式解码 | 复数频域掩码与重叠相加；解码细节和发布网络不完全相同 |
| 训练损失 | 重建损失加逐近场干扰源的编码空间对比项 | 当前以尺度敏感波形目标和静音／恒定目标误差为主；不含逐近场负样本 |
| 时序 | 论文与发布实现的因果和归一化行为需要分别检查 | 当前块可用后续 80 ms；递推历史按当前块提交，边界频谱另行缓存 |

原公开代码的 VideoBlock 默认 LSTM 轴语义与论文描述存在差异：默认输入形状和 batch_first=False 的组合使其沿批次而非预期视频帧维递推。将论文文字、发布代码、当前模型三个对象分开审查，才能判断比较对象及潜在跨样本影响。详见 [论文差异复核](20261112-paper-streaming-plan-review.md) 和 [项目约定](../../AGENTS.md)。

历史长度按通路解释：默认时间卷积 kernel 5、dilation 16、帧移 8 ms，最远直接访问 512 ms 前的卷积输入；历史注意力默认缓存 125 帧，约 1 秒；时间 LSTM 的状态可跨块延续，能有效记住多久依赖训练。一次 2 秒训练样本从独立初始状态开始，理论递推长度与已验证的长期记忆是不同概念。

## 四、数据、切片和损失必须保持同一时钟

官方索引记录训练 100826、验证 9133、测试 9169 条，模型使用第 0 音频通道。训练与验证的主协议使用官方 tr/cv，官方 tt 留作测试；基于来源分组的派生划分用于补充泛化检查。官方不同 split 的部分源路径存在重合，分组持出与官方划分应分开命名。

训练目标为 2 秒，但最后一个 120 ms 输出块从 1.92 秒开始；完整的最后一块加 80 ms 前视需要读取到 **2.12 秒**，即 33920 采样点和 53 帧视频。仅截取 2 秒再补零会丢掉长录音已有的未来上下文。当前数据器按混音、目标音频和嘴图中最短的完整 40 ms 对齐帧数确定可用边界：min(len(mix)//640, len(target)//640, len(frames))。边界内保留真实后续输入，只对前 2 秒目标计算损失；目标不足 2 秒时补零后整段参与损失。越过这一对齐边界的输入补零，不足一个完整 40 ms 的尾部不计入可用帧。详见 [RealSSA 前视数据器](../../tools/streaming/realssa_lookahead.py) 和 [训练分块](../../tools/streaming/lookahead_training.py)。

公开 TAR 每条包含混音、目标、嘴图和元数据，未直接提供逐个近场干扰源的时间对齐混响波形。混音减目标是其他干扰和噪声的合成，不能称作某个独立说话人的参考。服务器发现部分原始 LibriSpeech 归档；是否可完整恢复各源及其原混响，需要逐项检查生成素材、裁剪、增益和房间响应。项目旧近场加载代码会从元数据路径读取干声，代码口径与论文描述须分别说明。

### 当前损失和三个相似名称

正常语音训练与验证使用直接波形信号和误差能量比：

    loss = 10 log10((Σ(output - target)² + 1e-8) / (Σtarget² + 1e-8))

该式不去均值、不对输出进行尺度投影；目标完全恒定时使用相对混音功率归一化的对数波形误差。全零目标计入 silent；非零恒定目标计入 degenerate。实现见 [尺度敏感损失](../../tools/streaming/scale_sdr_loss.py)。

- **当前波形训练目标**：直接目标与误差能量比，整体音量错误会受到惩罚。
- **SI-SDRi／SI-SNRi**：对预测进行尺度对齐后计算相对混音的改善，训练后保留此类测试指标。
- **BSS Eval SDRi**：项目其他评估使用的滤波版本，和上述直接波形目标不是同一指标。

推理入口另输出 waveform_snr_db 与 waveform_snri_db。其逐段均方能量下限和静音有效样本筛选与训练能量求和、平滑项不同；名称和有效分母应随结果记录。详见 [检查点推理与指标](../../tools/streaming/infer_paper_lookahead.py)。

## 五、数值异常不是单一现象

旧的宽度 256 训练从第 394 步开始出现明显梯度异常：当时学习率约 0.00394、未裁剪梯度范数约 7182；第 400 步约 201310。第 9 轮完整验证损失约 146 万，之后异常继续扩大；在 epoch=22 的第 1086 次成功更新之后，程序检测到非有限梯度并自行退出。学习率上升与异常同时出现，日志不能单独证明学习率是唯一原因。

对官方 cv 样本 00004_01_80328 的逐层回放发现：

1. 该条目标全静音，混音 RMS 约 0.09；旧模型输出峰值约 5 万。FP32 和 BF16 回放都出现大幅放大。
2. 从注意力输出到跨尺度融合、逐级上采样和解码，激活逐层增大；无界复数掩码进一步把异常增益传到输出。
3. SI-SDR 对整体尺度不敏感，非静音样本的输出音量已经明显膨胀时，语音 SI-SDR 仍可能没有暴露同等程度的问题。
4. 旧静音项为未压缩的归一化 MSE；单条异常样本就能主导全量验证均值和整个训练 batch 的梯度。
5. 旧调度器在预热期间未跟踪完整验证的最佳值，等到调度开始时基准已经严重恶化。

修复版对注意力、融合和解码位置使用逐帧逐频点归一化；掩码偏移使用 4*tanh(x/4) 平滑限幅。旧权重混合加载到新架构的单样本诊断中，同一异常样本输出峰值降至约 0.170；该探针用于定位数值效应，不能当作重训后的质量结果。之后用户要求将正常语音主损失换成上节的直接波形目标，不再使用当轮的 SI-SDR 加波形辅助项。

预热期间现在记录完整验证的最佳结果；验证恶化时可调整后续学习率缩放。任一卡梯度范数非有限或超过配置阈值 1000 时，两卡一致跳过本次更新并降低缩放；连续异常达到上限时退出。监控同时记录语音、静音、恒定目标数量、各类损失、输出峰值和输出／混音 RMS 比。证据与阈值由来见 [异常复核](20261112-lookahead-training-instability.md)、[调度代码](../../tools/streaming/robust_schedule.py) 和 [监控代码](../../tools/streaming/stability_metrics.py)。

## 六、大 batch、显存和 CPU 上限要实测

一次完整 batch 的优化语义和内部计算切片不是同一件事。当前每卡仍接收 1024 条，内部每 256 条进行激活重算并拼接输出，再统一计算完整 batch 损失，执行一次反向和一次优化器更新；不是多个 batch 梯度累积。BF16 下切片改变算子批形状，会产生正常舍入差异，因此使用输出与梯度容差检查，不宣称逐位相同。

数值修复后的宽度 256、hidden 320 候选，在双卡每卡 1024 的真实数据试跑完成一次更新，最大已分配显存约 31.152 GiB／卡；这只证明该步能运行。官方训练 100826 条，2 卡全局 batch 2048，当前 drop_last 每轮执行 49 次更新，处理 100352 条，当轮剩余 474 条不参与该轮更新；后续轮次重新洗牌，具体覆盖以样本索引审计为准。

CPU 候选测量使用服务器 4 线程、预热 100 块、测试 500 块，包含冻结 FRCNN 与音频核心：

| 宽度 / LSTM hidden | P50 | P95 | P99 | 最大 | ≥60 ms 块数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 192 / 256 | 31.34 ms | 33.72 ms | 36.20 ms | 40.24 ms | 0 |
| 256 / 320 | 40.52 ms | 44.05 ms | 46.62 ms | 156.70 ms | 1 |

记录分别位于服务器 experiments 下 falcon_paper_lookahead_20261112/full_stable_split_w192_cpu4.json 和 full_stable_split_w256_cpu4.json。正式配置选择宽度 192。上述是指定硬件、线程、随机输入、预热和测量样本下的结果；生产负载、不同机器与最终训练权重需要重新测量。2 秒窗口推理时间、中位数和块级最大值回答不同问题。
