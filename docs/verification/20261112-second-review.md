## 已确认的问题与处理

1. **输入已接受、处理失败时的恢复。** 会话此前在 processor 抛错或返回错误输出时，未明确重试已接受 tick 的协议；处理器输出中的非有限数也可能进入调用结果。现行会话校验输出长度与有限性：`push()` 已接受 tick 后，processor 失败则保留队列及旧状态，使用 `retry_ready()`，不重复提交同一序号。输入序号、形状或有限性在接受前校验失败时，修正后可以重发同一 tick。流尾 `finish()` 中途失败时重新调用 `finish()`；尾块保留到整个收尾成功后返回。
2. **状态的回滚边界。** 此重试协议要求 processor 将传入状态视为只读并返回新状态；会话不能撤销外部 processor 对传入对象的原地修改。重叠相加的边界频谱与卷积、LSTM、注意力历史也各有独立的提交语义。
3. **训练配置重复键和数值类型。** 旧训练入口使用 `yaml.safe_load`，重复 YAML 键可能被后一个值覆盖，不能依赖字面配置判断实际生效参数。复核副本改为重复键检测，并检查必要键、整数／布尔类型、有限数值和参数范围；这是防止误配置的后续修复，不表示当前实际训练配置有重复键，也不表示该问题造成此前训练爆炸。
4. **在线调用和性能口径。** 新增 [PaperLiveInference](../../tools/streaming/paper_live_inference.py) 将检查点、模型与流式会话连接，接收按序到达的 40 ms 音频和已归一化嘴帧；人脸跟踪、嘴部裁剪、采集及网络不在此接口中。设置 `threads` 会改变当前 PyTorch 进程的线程数。可复用的完整会话基准见 [benchmark_paper_live.py](../../tools/streaming/benchmark_paper_live.py)。
5. **文档与技能术语。** 原 Falcon 配置使用 `n_src: 1`，新流式模型固定输出一路但 YAML 不含该字段；非零恒定目标不一定低能量，当前损失将其作为 degenerate 单独处理。旧 SI-SDR 加增益辅助项仅属于历史训练。SSH 技能同时覆盖本机 Cursor 和服务器 Git 故障后，排查步骤也相应区分连接方向；处理本机连接失败不要求先检查 Git 仓库。
