## 几个最容易混用的结果

- RealSSA-Sim 两份全量 CSV 的 SI-SNRi 各有 9,169 个有效值，SDRi 和 PESQ 各有 9,166 个；模型输出条数和某个指标的有效数应分别报告。
- `DNSMOS-realssa-real-mean-full3/` 是窗口起点错误的历史记录；[full4](phase2/DNSMOS-realssa-real-mean-full4-20261031/)记录 54 段，但论文所用权重身份尚待确认，且其窗口边界处理与 Studio 存在差异。
- 2026-11-08 两种流式脚本的输入和处理方式不同。`streaming_consistency.py` 的帧选择会在部分对齐位置重复/跳帧；`streaming_canonical.py` 的相位筛选曾包含同网格组合。本轮对照采用特定条件下的拼接输入。具体文件与结果见[时间依赖说明](../understanding/20261110-model-and-streaming.md)。
- 2026-11-10 的服务器 CPU 复现测试为 **166 passed / 2 skipped**，跳过项依赖已不在原路径的历史临时文件；早先的 **168 passed** 来自测试资产齐备时的运行。
- 早期验证脚本使用的 `docs/verification/stubs/` 包含 timm、typeguard 及数据处理替身。阅读对应日志时可根据导入路径区分替身与真实依赖。

## 如何复查

1. 先看结果所在报告的权重、数据、通道、窗口、条数与指标定义。
2. 到对应 CSV 查看逐句行和有效数；结果行与平均值用于检查表内统计，输入身份和模型推理需结合日志与脚本查看。
3. 再看日志及运行脚本是否使用真实权重、真实视频、随机输入或 mock，是否有跳过、异常、覆盖输出与环境替身。
4. 如果要重跑，使用独立输出目录并记录代码版本、输入/权重哈希、命令和失败范围。原始日志与 CSV 保留；修正结果另存带日期的新文件。

本轮对 25 份 CSV 做了格式及相应数值核查：18 份逐句表重算均值/总体标准差，5 份 DNSMOS 表重算有效值均值，其中 full3/full4 再与各自摘要对照；2 份训练表检查有限训练步和单调性。这次核查使用保存的指标表。四份关键全量表与**当前**测试索引的 ID 集合比较未发现缺漏；历史运行时的索引文件未保存。

需要复现本轮三个小探针，可先读 [2026-11-10 证据说明](deepdive-20261110/README.md)中的命令和写入位置。部分历史命令会向固定目录写日志、重新生成索引、下载数据或删除迁移后的源文件；运行前查看对应脚本的实际写入位置。
