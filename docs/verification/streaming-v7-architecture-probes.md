# 120 ms 流式 Falcon 的历史上下文与输出表示探针

固定抽取派生开发集的 24 条样本，随机种子为 `20261113`。按相同的中心 2 秒裁剪、第 0 音频通道、88×88 归一化嘴图和 SI-SDRi 计算逐条配对。旧流式模型使用此前 136 轮训练的 `final.pt`，开源模型使用本机缓存的 `falcon.pt`。样本 ID、输入摘要与逐条值见服务器实验目录 `/root/group-shared/voiceprint/experiments/falcon_synthesis_oracle_20261113/`。

## 前缀推理保留了多数整段质量

| 同一开源权重的推理方式 | 平均 SI-SDRi |
| --- | ---: |
| 2 秒整段 | 7.814 dB |
| 按 120 ms 推进，每次重算到当前块结束的全部前缀 | 7.019 dB |
| 每次输入固定 2 秒，当前块之后以零填充 | 5.861 dB |
| 每个 120 ms 块独立执行 | 2.854 dB |
| 旧流式模型，带原有状态 | 5.070 dB |

纯前缀从 120 ms 开始逐块增长。每次重新提取已到达嘴图的特征，执行整段模型，只截取当前块对应的输出。最后一块是原 2 秒范围内的 80 ms。每次调用只提供到当前块为止的真实输入。固定长度补零实验向开源模型提供合成的未来输入，改变了窗口归一化和递推边界。独立块实验还切断了历史。

纯前缀平均比整段低 **0.795 dB**，在 **21/24** 条上超过旧流式，平均高 **1.950 dB**。在这批样本中，限制输入只到当前块时，较强的估计器依然能获得更好的结果。纯前缀重复计算历史，运算量随片段增长。这个探针检验可用信息和实际质量，未作为 CPU 部署方案测速。

证据为 `prefix_probe.py`、`prefix_probe.log`、`prefix_results.json`。

## 原有解码器具备超过当前模型的可达解

当前合成把每个 8 ms hop 的 129 个实频率系数做逆实 FFT，只保留 129 个因果抽头，以 overlap-save 输出当前 128 点。实频率坐标映射到这 129 个抽头的矩阵是可逆的余弦变换。原模型的 sigmoid 将每个系数限制在非负区间。可带符号的 129 个实频率系数能表达任意实数因果抽头，无需额外的复数分支。

诊断按 hop 构造线性合成矩阵，并以随机系数逐点核对矩阵输出和项目实际 FFT 路径。在同一 24 条样本上，用真实目标指导求解，每段分别拟合正、负目标的去均值波形，记录两种极性中较高的 SI-SDRi。非负解按整段统一比例缩到 0–1 区间，保持 SI-SDR 的尺度关系。非负优化从常数 0.25 开始，有符号优化从全零开始，两类解使用相同的固定迭代预算。统计为求解器已经达到的值。

| 掩膜拟合范围 | 300 次迭代 | 600 次迭代 | 1,200 次迭代 |
| --- | ---: | ---: | ---: |
| 非负系数，可统一缩放 | 14.825 dB | 15.215 dB | 15.336 dB |
| 可带符号系数，可统一缩放 | 20.976 dB | 24.574 dB | 28.207 dB |

同组样本上，旧流式平均为 5.070 dB，开源整段为 7.814 dB。非负探针找到的输出已高于开源整段，有符号参数进一步扩大了合成解域。两种拟合均读取真实目标，可达分数和可训练模型的分数需要分开。尤其有符号解在 600 至 1,200 步间仍继续提升。

证据为 `oracle_signed_fair.py`、`oracle_signed_fair.log`、`results_signed_fair.json`。

## 有符号解码与历史注意力实现

v6 在原 sigmoid 路径上叠加零初始化的线性输出，给每个 hop 提供有符号频率修正。两条路径仍共享原 129 抽头合成，输出长度与 120 ms 接口保持一致。迁移旧权重后零残差逐样本复现原输出。

v7 用当前块的 15 个音频 token 和 3 个视频 token 查询历史投影 K/V 与本块 K/V。每块仅为当前 token 执行投影，历史缓存容量由 `attention_history_chunks` 指定。16 块容量覆盖此前 1.92 秒，缓存按先进先出保留最近的完整块。长历史与原块内注意力之差经零初始化标量门控加入。门控为零时，v7 与同权重 v6 的输出逐样本相同。门控开启时，修改历史值缓存会改变当前块输出。

模型定向回归 **20 项通过**，覆盖 v4 至 v7、零残差、零门控、缓存长度和尾部保留、格式不匹配拒绝、分别扰动后续音频和视频。CPU 实输入边界审计对 4 种未来扰动测得过去块最大绝对差为 **0**。模型初始化 CLI 创建了 8 块历史的未训练检查点。16 块门控开启的实际检查点经过严格加载、HTTP 状态、WebSocket 会话间隔离及 reset 验证。

## 并发负载下的 CPU 处理耗时

使用从短试验 v6 权重迁移的 v7 检查点，将门控设为 1，启用 16 块历史。在 Xeon Platinum 8336C 上固定 4 个物理核与 4 个 PyTorch 线程，输入为一个 LRS2 片段的 16 块循环。20 块预热后按 120 ms 节奏连续处理 500 块。测量包括嘴图裁剪归一化、音视频前向和输出复制。该次测量与训练、教师缓存和回归任务重叠。

| 指标 | 耗时 |
| --- | ---: |
| 处理 P50 | 20.11 ms |
| 处理 P95 | 27.85 ms |
| 处理 P99 | 53.38 ms |
| 处理最大 | 170.19 ms |
| 从计划释放到开始最大 | 50.27 ms |
| 从计划释放到完成 P99 / 最大 | 72.50 / 170.26 ms |

500 块中有 **5 块处理达到或超过 60 ms**，其中 2 块达到或超过 120 ms。此轮并发测量未通过逐块 60 ms 的门槛，需在最终选中的检查点上测独占资源条件，并记录真实运行负载。

证据为 `cpu_history16_paced500.json`、`causality_history16.json`、`v7_server_smoke.json`。
