# 2026-11-11 目录快照工具复核

[snapshot_catalog.py](snapshot_catalog.py) 只读取多模态登记、状态、归档回执和两侧目录入口，写出用户指定的新 JSON。2026-11-11 使用虚构数据与实际登记表进行了多轮检查。

第一轮发现来源 URL 中的用户名、密码可能保留，敏感字符串可能出现在自由文本；写出中途失败也可能留下不完整文件。随后对来源 URL 去除 userinfo、查询与片段，对字段执行已定义模式筛查，使用同目录临时文件和原子硬链接发布，不覆盖已有目标并清理失败的临时文件。

第二轮发现单独匹配 `authorization` 会误删真实的 `authorization_requested` 状态和 `AUTHORIZATION_STATUS_zh.md` 文件名；现将检测限定到授权头或赋值形式。复核还发现敏感值可能被误填为 slug、URL 路径可能使用编码；现拒绝敏感 slug，并检查解码后的来源主机与路径。该检查是明确列出的模式，结果不能替代对未知秘密形式的审查。

合成测试覆盖：URL userinfo 与查询移除、单层及双层编码路径、敏感 slug、合法状态和文件名保留、采集开始/结束及两侧目录读取时间顺序、旧文件不覆盖、无效 JSON 失败后临时文件清理。实际目录重新读取得到 **37 个登记项**；登记状态仍以工具每次运行时的采集时间为准。各媒体并未因生成快照而被重新哈希或逐条解码。
