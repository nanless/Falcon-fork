## 2. 一条训练样本是什么

Falcon 做的是目标说话人提取：以多个人的混音和目标人的嘴部为输入，输出这个人的一路声音。训练时需要该目标的参考语音作为标签；传统 Falcon 对比损失路径可再读取干扰人的参考音频。

```text
mix.wav      两人或多人混合录音 ─┐
mouth.pt     目标说话人的嘴部帧 ─┼─> 模型 ─> 目标说话人输出
target.wav   同步的目标干净/参考语音 ─────> 训练损失、SI-SNRi / SDRi
near.wav     可选干扰音频 ─────────────────> 传统训练的说话人对比项
```

输入索引为 UTF-8 JSON 数组，每个位置使用同一条样本：

```text
mix.json    [[混音绝对路径, 音频采样点数], ...]
target.json [[目标语音绝对路径, 目标嘴图绝对路径, 音频采样点数], ...]
near.json   [[[干扰语音绝对路径, 采样点数], ...], ...]
```

当前 LRS2 的一条例子：`mix.json` 指向 `tr/mix/5535415699068794046_00004_2.4022_6160231649911868423_00015_-2.4022.wav`，目标在 `tr/target/` 下同名，嘴部为 `tr/mouths/5535415699068794046_00004.pt`；其 near 指向源数据对应的 `s2/` 同名文件。首条实测混音、目标均为 16 kHz、单声道、PCM16、32,000 点，嘴图 `.pt` 是 `torch.uint8 [50,96,96,3]`，对应 25 fps、2 秒。转换后的 RGB 三通道来自原始灰度嘴图的复制，模型预处理后使用 88×88 灰度图。

LRS2 发布的 `s1` 与 `s2` 已包含混音时的增益；已有抽样显示 `mix≈s1+s2`，误差在 PCM16 量化量级。文件名里的增益标签不是逐条整段 RMS 比值。近场索引使用的是另一名说话人的混音分量，并非另行录制的近场泄漏轨；[近场索引核对](../verification/phase2/P2C-near-mode-provenance.md)记录了转换时 `fallback` 统计与后来实际 `near.json` 的差异。

### 2.1 哪些代码真的读取了它

| 入口 | 数据选择 | 一条输入的实际裁剪和目标 |
| --- | --- | --- |
| [`configs/LRS2_2Mix.yml`](../../configs/LRS2_2Mix.yml) + 原训练入口 | `/root/data/falcon_lrs2_2mix/{tr,cv,tt}` | 16 kHz、`segment=2.0`、`n_src=1`，训练启用 `use_near` |
| [`configs/LRS2_2Mix_Paper_v2.yml`](../../configs/LRS2_2Mix_Paper_v2.yml) 及对应 2/8 GPU 配置 | `/root/data/falcon_lrs2_2mix_paper/{tr,cv,tt}` | 结构相同，但同一个混音在两个方向分别出现 |
| [`tools/streaming/train.py`](../../tools/streaming/train.py) | 命令行 `--index-dir`，例如 `/root/data/falcon_lrs2_2mix/tr` | 读取 `mix.json` 与 `target.json`，按 640 音频采样点对齐 25 fps 嘴图，不读取 `near.json`；负 SI-SNR 损失 |
| [`tools/streaming/infer.py`](../../tools/streaming/infer.py) | 明确传入 `--audio`、`--mouth` | 一次处理 2,560 个采样和 4 张嘴图；最后短块补齐后输出按原始长度裁回 |
| [`audio_visual_test.py`](../../audio_visual_test.py) | 指定测试索引和权重 | 有参考目标时可算 SI-SNRi、SDRi 等；输出与混音基线同口径比较 |
| [`tools/repro/phase2/eval_realssa_real.py`](../../tools/repro/phase2/eval_realssa_real.py) | RealSSA-Real inference 清单 | 用真实录音和嘴图分离，再使用 DNSMOS 等无参考指标；没有对齐干净目标波形 |

`configs/Falcon.yml` 中的数据路径仍是 `--` 占位符。`configs/FalconStreaming.yml` 是格式和默认参数参考，流式脚本不读取此文件；实际数据由命令行决定。原训练加载器默认 `respect_index=False`，每次从样本池有放回随机抽取；`train_samples: 10000` 是一个 epoch 的抽取次数。对双向训练池，40,000 是目标方向数，不是 40,000 个不同混合。新流式训练使用普通 DataLoader 按索引选样，并在每条内按 640 采样网格选起点；两者的采样协议不同。

新流式训练默认 `--chunks 10`，即每条训练片段 1.6 秒，20 段 8 ms 处理步对应一个 160 ms 块。对固定 2 秒的 LRS2，裁剪起点以 640 采样（40 ms）为单位在 0 至 6,400 采样之间选择。该脚本不读取近场对比语音。

## 3. LRS2-2Mix：训练、验证和测试

源数据位于 `/root/data/lrs2_2mix/lrs2_rebuild`；其中 `audio/wav16k/min/{tr,cv,tt}/{mix,s1,s2}` 是项目使用的 16 kHz 音频，`mouths/*.npz` 是原始嘴部灰度帧。源目录另外包含 8 kHz 音频副本、原始片段、人脸视频、特征点和混音清单。`mix`、`s1`、`s2` 每条是 2 秒；混合由两位说话人组成。

2026-11-11 对 JSON **所有条目**计数并统计不同路径：

| 目录及划分 | 索引方向数 | 不同混音路径 | 不同目标音频路径 | 不同嘴部路径 | 索引累计音频时长 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `/root/data/falcon_lrs2_2mix/tr` | 20,000 | 20,000 | 20,000 | 14,773 | 11.111 小时 |
| 同目录 `cv` | 5,000 | 5,000 | 5,000 | 476 | 2.778 小时 |
| 同目录 `tt` | 3,000 | 3,000 | 3,000 | 267 | 1.667 小时 |
| `/root/data/falcon_lrs2_2mix_paper/tr` | 40,000 | 20,000 | 40,000 | 18,691 | 22.222 方向小时 |
| 同目录 `cv` | 10,000 | 5,000 | 10,000 | 476 | 5.556 方向小时 |
| 同目录 `tt` | 6,000 | 3,000 | 6,000 | 267 | 3.333 方向小时 |

双方向将同一混音分别与 s1、s2 的目标语音及对应嘴图配对，所以方向小时是不同混音物理时长的两倍。嘴图按目标原片段复用，一名目标可出现在多个混音中，嘴图数少于样本数不代表缺样本。

抽查范围：每个目录的每个划分按等距选取 30 个索引位置，检查 mix、target、mouth、near 指向的文件，缺失为 0；实读每划分首条音频头和嘴图张量。该抽查没有逐条读取全部音频波形。整表唯一数和时长来自全部索引，音频的时长以索引采样点和 16 kHz 计算。单方向和双向部分嘴部文件共享硬链接，统计空间时需要辨认实际对象。

原 Falcon 的旧训练记录使用单方向 LRS2；已有完整测试在单方向 3,000 条上运行。双向配置是论文对齐方向的索引，不能把双向 6,000 条当作 6,000 个不同混音，也不能把历史单方向结果直接说成双方向测试结果。

## 4. RealSSA-Sim：仿真混音和多源场景

RealSSA-Sim 的原包每条有 `*.mix.wav`、`*.target.wav`、`*.mouths.pt`、`*.json`：音频为 16 kHz 4 通道 PCM16，嘴部为 uint8 彩色 `[帧数,96,96,3]`，JSON 描述声源、房间、场景和位置。目标语音/嘴部来自 LRS3；模拟场景还使用不同背景声音和干扰语音。论文数据卡报告训练 100,826、验证 9,133、测试 9,169 条；[现有详细说明](../understanding/20261110-datasets.md)列有数据卡所述时长、来源比例和历史核验条件。

服务器 2026-11-11 实际看到：

| 位置 | 状态及内容 |
| --- | --- |
| `/aispeech-cfs/voiceprint/data/multimodal/realssa_sim/tr` | 202 个 tar |
| 同目录 `cv` | 19 个 tar |
| 同目录 `tt` | 19 个 tar |
| `/root/data/RealSSA-Sim/tt` | 本机测试原始分片 |
| `/root/data/falcon_realssa_sim/tt` | 9,169 条已转换，4 通道取平均得到单声道 |
| `/root/data/falcon_realssa_sim_ch0/tt` | 9,169 条已转换，取第 0 通道 |

两套转换索引各自的 9,169 行总时长约 11.735 小时，采样点范围为 16,000–120,320，即约 1.0–7.52 秒；这是两种处理同一测试集，不是两套独立样本。首条 `00001_00_10182` 的混音与目标为 16 kHz、单声道、92,800 采样，嘴图为 uint8 `[145,96,96,3]`，均对应 5.8 秒。两种转换各按等距 30 条检查索引路径均存在，首条实际读取音频头和嘴图。

两套 `near.json` 的 **9,169 条**都指向相应混音本身。原 Falcon 加载器跳过这个自引用，占位不构成单独的 near 波形；如果需要近场对比负样本，需准备与场景对齐的实际独立波形。新流式训练入口不读取 near，若使用该训练路径可按索引读取 mix、target、mouth，但当前本机仅有 `tt` 转换集，不能把它用作训练而又当独立测试集。

[`tools/repro/realssa_to_falcon.py`](../../tools/repro/realssa_to_falcon.py) 将原始多通道样本选指定通道或平均并转换为项目索引。它的输入数据、输出目录和通道策略应在新实验中一并记录；不要把均值与第 0 通道结果合并成一组。

流式文件回放当前要求 16 kHz 单声道 WAV 与 25 fps `.pt` 嘴图；RealSSA-Real 的原始双声道 WAV 与 `.npz` 嘴图需要明确选通道、对齐并转换，才能接入该入口。源文件和转换结果分别记录，以便复测。

## 7. 如何为新数据判断可用性

1. **训练监督**：是否有混音、与混音同一时间轴的目标语音、与目标身份一致的嘴图；只有干净说话视频时，可以作为合成混合的源素材，但还不是现成的混音训练条目。
2. **实际格式**：音频是否能转成 16 kHz 单声道；嘴图是否为 25 fps、96×96、uint8，以及起始时间和目标音频的对应关系。新流式入口读取 JSON 绝对路径并逐条检查 mix 与 target 文件名；不满足时需转换索引或扩展加载器。
3. **数据划分**：检查说话人、源视频、目标片段和衍生混合是否跨训练/验证/测试重复；同一混音的两个目标方向应属于同一划分。
4. **评测作用**：有对齐 target 才能算有参考分离指标；真实场景可用 DNSMOS、人工听评、识别和说话人相似度等，但与带干净 target 的数据不是同一评测口径。
5. **存储位置**：先确认本地路径、共享文件系统、TOS 对象和各自的样本/分片身份。TOS 冷数据在需要使用时可以按后续确认的对象路径下载到合适的存储，再做完整性与索引检查；对象是否可读以对应存储盘点为准。
6. **来源约束**：保留数据集来源、访问条件和适用范围，核对用于特定训练或发布的授权。
