# 块级因果流式模型实施计划

> **Execution:** 使用已安装的 `executing-plans` 工作流执行，沿用用户已授权的改造、复核和提交推送范围。

**Goal:** 实现 160 ms 块内音视频互看、块间不看未来的有状态流式目标说话人提取。

**Architecture:** 在既有因果卷积和音视频前端后加入仅处理当前块的轻量联合注意力，使用既有历史缓存，并保留对齐的重建方法。训练和推理共享块级执行接口。

**Tech Stack:** Python、PyTorch、pytest、项目现有流式会话和基准脚本。

## 实施与验收

1. `look2hear/models/FalconStreaming.py`：增加本块 20 个音频特征和 4 个视觉特征的联合交互，升级模型状态版本；检查形状、梯度和未来块隔离。
2. `tools/streaming/`、`configs/FalconStreaming.yml`：更新检查点版本、逐块训练/推理和因果审计，沿用会话状态与时间戳规则；执行随机检查点和真实数据短训、续训。
3. `tools/repro/tests/`：覆盖块边界因果性、块内交互、历史状态、训练与推理一致、重建对齐及检查点版本；运行流式和相关回归测试。
4. `docs/FALCON_STREAMING_160MS.md` 与项目入口：说明块内互看、缓存、延迟、训练和旧版结果身份；追加本轮 CPU 和因果测试原始结果及复核记录。
5. 使用新检查点在 CPU 上按 160 ms 节奏进行长流测试，记录线程数、测试输入、处理和排队耗时以及 P50/P95/P99/最大值；根据结果修复并复测。
6. 由其他 agent 复核实现、训练和文档，处理发现的问题；提交前执行状态和差异检查。完成后由服务器中文详细提交并推送当前分支。
